# agent-duet

Claude и движок-делегат, **Codex** (по умолчанию) или **agy** (Antigravity CLI), сами проводят между собой ревью, реализацию или аудит. Копировать текст между чатами не нужно:

- **Ревью** (`plan`, `code`, `file`): движок проверяет план, твои изменения в git или любые файлы. Claude по каждому замечанию либо исправляет, либо возражает с доказательствами, либо оставляет решение тебе. Цикл идёт, пока они не договорятся, не упрутся в тупик или не кончатся раунды.
- **Build** (`build`): движок реализует спецификацию, которую написал Claude, в отдельном git worktree, а Claude как архитектор проверяет каждый раунд. Основная работа идёт из лимита выбранного движка, а не Claude.
- **Аудит** (`audit`): движок изучает код, данные или документы, ничего не меняя, и выдаёт разовый отчёт с находками. Переговоров нет.

Все пять режимов работают с обоими движками. Начать можно командой `/agent-duet` или просьбой словами; `/duet` открывает панель, где видно, как идёт работа. Плагин состоит из двух частей: **раннер** (`scripts/duet.mjs`) запускает ходы движка и ведёт запись каждой сессии, а **мод** Claude Code (`hooks/register.tsx`) рисует панель, строку над промптом и уведомления и добавляет хуки цикла и защиты от коммитов. Раннер за тебя запускает Claude.

> До версии 0.12.0 плагин назывался **codex-duet**. Сессии, настройки, переменные окружения и ветки `codex-duet/` переходят сами; подробности в разделе [Переход с codex-duet](#переход-с-codex-duet).

## Установка

### Что нужно

- Claude Code 2.1.275 или новее.
- Установленный движок, в котором выполнен вход: [Codex CLI](https://github.com/openai/codex) с `codex` в `PATH` или agy (Antigravity CLI, проверено с 1.5.7) с `agy` в `PATH`. Другой бинарник задают `AGENT_DUET_CODEX_BIN` или `AGENT_DUET_AGY_BIN`.
- Node.js 22 или новее: раннер написан на Node.
- git для режимов code и build.

### Где работает

| Платформа | Что работает |
|---|---|
| macOS | Всё |
| Linux | Всё, кроме звука: у Claude Code на Linux нет проигрывателя, но тосты и строка над промптом работают. Если раннер убили через `kill -9` или машина упала, удали оставшуюся от него блокировку сессии сам: ошибка `stale lock` называет файл. (На macOS ядро снимает такую блокировку само, `O_EXLOCK`.) |
| Windows | Не поддерживается: раннер и мод вызывают `kill`, `tail`, `head`, `grep` и `diff`. WSL должен вести себя как Linux, но не проверялся |

Если Claude Code управляется организацией (managed settings), хук `Stop` не запускается в плагинах, которые ты поставил сам, и мод не может вернуть Claude в цикл, когда тот закончил ход (см. [Цикл не останавливается сам](#цикл-не-останавливается-сам)). Остальное работает.

### Как поставить

В терминальной сессии Claude Code:

```
/plugin install agent-duet --marketplace VScheglov/agent-duet
```

На вопрос `Add marketplace?` ответь `y` и выбери область: с user плагин работает во всех проектах. То же из оболочки:

```bash
claude plugin install agent-duet --marketplace VScheglov/agent-duet
```

В приложении Claude, где `/plugin` не работает: нажми **+** рядом с полем ввода, затем **Plugins**, **Add marketplace** с `VScheglov/agent-duet` и **Add plugin**.

Если `/agent-duet` и `/duet` после установки не видны, открой новую сессию или выполни `/reload-plugins`. Полное имя команды скилла `/agent-duet:agent-duet`; короткое `/agent-duet` работает, пока это имя не заняла другая команда.

### 12 часов на фоновую команду (рекомендуется)

Ход движка может идти часами, поэтому Claude запускает его фоновой командой с `timeout: 43200000` (12 часов). Без настройки Claude Code ограничивает фоновые команды 2 часами и обрывает более долгие ходы; тогда можно попросить Claude сделать `retry`, и он продолжит тот же разговор с движком, если это возможно. Чтобы поднять предел, добавь в `~/.claude/settings.json`:

```json
{ "env": { "BASH_MAX_TIMEOUT_MS": "43200000" } }
```

Настройка действует в сессиях, открытых после правки. Заодно она поднимает до 12 часов и предел тайм-аута для команд на переднем плане.

## Использование

```
/agent-duet plan                      ревью плана из plan mode или из разговора
/agent-duet code                      ревью незакоммиченных изменений (вместе с untracked)
/agent-duet code --base main          ревью всей ветки от merge-base с main
/agent-duet file docs/spec.md         ревью любых файлов: тест-кейсов, SQL, спек, конфигов
/agent-duet build                     движок реализует задачу в своём worktree
/agent-duet audit                     разовый аудит без изменений, с отчётом о находках
/agent-duet code -- проверь миграции  после `--` идёт фокус
/agent-duet code --engine agy         agy вместо Codex (в любом режиме)
/agent-duet status                    где мы сейчас (пригодится и после сжатия контекста)
/duet                                 открыть панель
```

Можно и словами: «отдай Codex на ревью», «отдай agy на ревью», «делегируй agy», «проведи аудит через agy».

**Кто что запускает.** Ты говоришь с Claude, а Claude ведёт сессию подкомандами раннера: `start`, `reply`, `review`, `retry`, `verify`, `finish`, `discard` и `status`. Где в этом README упоминается одна из них, её запускает Claude: достаточно попросить, например «повтори оборванный ход» или «заверши build».

**Движок** выбирается при старте сессии опцией `--engine codex|agy`. Без неё берётся `AGENT_DUET_ENGINE`, затем `codex`. Движок закрепляется за сессией: `reply`, `review` и `retry` его не меняют, для другого движка нужна новая сессия. В сессиях до 0.12.0 поля движка нет, они остаются сессиями Codex.

**Опции для обоих движков:** `--max-rounds N` (по умолчанию 10), `--model`, `--effort`, `--timeout-min` (лимит на ход; по умолчанию без ограничения) и `--sandbox` (по умолчанию `inherit`). Модель и уровень можно менять через `reply`, `review` или `retry`. Как их понимает каждый движок, описано в разделе [Различия движков](#различия-движков).

## Как идут переговоры

```
start ─► движок: замечания C1…Cn (JSON по схеме)
          │
          ▼
   Claude по каждому замечанию:  fixed · disputed · needs-user
          │
reply ─► движок (та же сессия, resume): resolved · withdrawn · open + контраргумент · новые
          │
          ▼
   scripts/policy.mjs → continue · done · escalate (тупик → тебе)
```

- ID замечания не меняется всю сессию. Движок видит ответы Claude и diff между раундами.
- Если ты решил спор в пользу текущей версии (`owner-decided`), замечание закрывается, даже если движок не согласен.
- Когда раунды кончаются, всегда происходит эскалация, что бы ни решила политика.
- Claude ничего не коммитит.

## Политика остановки (`scripts/policy.mjs`)

Правила проверяются сверху вниз, срабатывает первое подходящее:

1. Claude отложил решение с severity critical/high (`needs-user`) → **escalate** сразу.
2. Движок говорит `approve`, открытых critical/high нет → **done**. Medium/low уходят в отчёт, остальное отложенное приносится тебе.
3. Движок 2 раза отклонил возражения по одному замечанию → **escalate** (тупик).
4. Два раунда подряд открытых замечаний не становится меньше → **escalate** (застой).
5. Иначе → **continue**.

Пороги задаются константами `MAX_DISPUTES` и `STALL_ROUNDS`. Если меняешь правила, поправь и тесты `policy …` в `tests/run.mjs`.

## Режим build: движок пишет, Claude ревьюит

```
/agent-duet build                     «делегируй Codex …», «пусть Codex реализует …»
/agent-duet build --engine agy        «делегируй agy …», «пусть agy реализует …»
```

1. Claude пишет спецификацию: цель, границы, ограничения, критерии приёмки, как проверять.
2. Раннер создаёт ветку `agent-duet/<id>` в отдельном worktree от HEAD. Твоё рабочее дерево не трогается, а незакоммиченные изменения движок не видит.
3. Движок реализует, гоняет тесты и отчитывается: что сделал, что проверил, что под вопросом.
4. Claude смотрит дифф раунда, сам запускает тесты в worktree и поднимает замечания C1…Cn. Движок исправляет или возражает. [Политика остановки](#политика-остановки-scriptspolicymjs) та же, что в ревью; тупики приходят к тебе (и в панель `/duet`).
5. Когда всё сошлось и ты согласен, `finish` коммитит работу в ветку и убирает worktree, а сливаешь ветку ты сам. Заголовок в формате Conventional Commits (`feat: …`, `fix(scope)!: …`) становится темой коммита как есть; к любому другому добавляется префикс `agent-duet: `, если его там ещё нет. В теле коммита указаны движок, который выполнил работу, и ревью Claude. `discard` удаляет и worktree, и ветку.

Изменения после одобрения возвращаются новым раундом ревью; см. [Проверки и сверки](#проверки-и-сверки). Инструкции для Claude лежат в `references/build.md`.

## Режим audit: движок проверяет, ничего не меняя

```
/agent-duet audit                     «проведи аудит через Codex …», «пусть Codex проверит … и даст отчёт»
/agent-duet audit --engine agy        «проведи аудит через agy …»
```

Разовый отчёт без переговоров: аудит кода, данных, эталонного документа или политики, причём Claude не тратит токены на ответ по каждой находке. Ревью плохо подходит, когда Claude не может сам менять то, что проверяется, например эталон, который меняется только с твоего одобрения: почти каждая находка ушла бы к тебе. Не подходит и build: аудит ничего не должен менять.

1. Claude пишет задание: что проверить и на какой вопрос ответить, границы, что считать находкой, что вынести в заметки (рейтинг, таблицу).
2. Движок работает прямо в папке проекта, всегда в режиме `read-only`: другое значение `--sandbox` раннер не примет. Codex применяет свою песочницу с запретом записи из shell. У agy принудительного read-only нет: он запрещает `write_file`, а раннер после хода проверяет файлы и предупреждает об изменениях, не отменяя их, но shell-команды писать всё равно могут. Запись через MCP у обоих движков запрещена только промптом; см. [Безопасность](#безопасность).
3. Один ход. На выходе итог, находки A1…An (важность, место, доказательства, рекомендация, уверенность) и что проверено, а что нет. В сводке Claude по строке на находку, всё остальное лежит в `report.md` сессии.
4. Отвечать не на что: `reply` и `review` для аудита отказывают. Нужен другой угол — новый аудит с более точным заданием. Находки остаются утверждениями движка: прежде чем на них опираться, Claude проверяет нужные или говорит, что они не проверены.

Очередь, панель `/duet` (итог и находки), 12 часов на ход и `retry` работают так же, как в остальных режимах.

## Долгие ходы, повторы и параллельные задачи

**Время.** Ход движка идёт долго, build — особенно, поэтому Claude запускает `start`, `reply`, `review` и `retry` в фоне с `timeout: 43200000` (12 часов). Claude Code ограничивает фоновые команды пределом `max(2 ч, BASH_MAX_TIMEOUT_MS)` и молча обрезает до него более долгий тайм-аут; как поднять предел до 12 часов, сказано в [Установке](#12-часов-на-фоновую-команду-рекомендуется). На переднем плане команда без явного `timeout` живёт 2 минуты, в фоне — 30. Своего лимита на ход у раннера нет, пока не передашь `--timeout-min N`. Сессии, начатые до 0.6.0, хранят старый лимит в 60 минут; снять его можно командой `retry --timeout-min 0` (или с `reply`/`review`).

**Оборванный ход.** Если ход оборвался после того, как движок начал работу (кончилось время фоновой команды, нажали «Стоп», CLI упал), `retry` продолжает тот же разговор с коротким промптом «продолжи с того места», даже в первом раунде. Сделанная работа и прочитанное сохраняются, пока разговор доступен: Codex нужен журнал треда в `~/.codex/sessions`, agy — `.db` разговора в своём каталоге, и продолжает он его с `--conversation`. Иначе ход начинается заново. `retry --fresh` всегда начинает заново; сделанное на диске он не отменяет.

**Несколько задач сразу.** Можно делегировать несколько задач: у каждого build свой worktree и своя ветка. Одновременно на машине идут не больше десяти ходов движков (`AGENT_DUET_MAX_PARALLEL`), остальные ждут в очереди (фаза `queued`) в порядке постановки и стартуют сами, когда освободится слот. Каждый идущий ход поднимает все MCP-серверы из конфига движка, поэтому без очереди десять задач — это сотни процессов. Слот занят, только пока работает движок, а не пока Claude ревьюит. Время в очереди засчитывается в предел фоновой команды (2 часа по умолчанию, 12 с рекомендованной настройкой), так что лучше ставить по несколько задач, а не десятки сразу.

## Проверки и сверки

Раннер проверяет, что заявляют обе стороны, чтобы итог не держался только на их словах.

**Твоя просьба.** В ревью `plan`, `code` и `file` Claude передаёт Markdown-бриф (`start --brief <file|->`) с тремя разделами: `## Owner's request` (твои слова дословно; обязателен), `## Accepted amendments` (только принятые тобой поправки, каждая с источником) и `## Claimed result` (что, по словам автора работы, она даёт). Спецификация build сама должна содержать просьбу и может перечислять поправки; отдельного `--brief` у неё нет. Аудит бриф не принимает. Движок, а перед одобрением build и Claude, каждый отчитываются полем `request_check`: соответствует ли работа твоей просьбе. Сужение просьбы, о котором движок сообщил в ревью, или разногласие сторон в build приходит к тебе. Обе проверки видны в сводке, `status` и отчёте.

**Одобрение привязано к дереву, прошедшему ревью.** В build `finish` сверяет и worktree, и коммит после хуков; содержимое, изменившееся после одобрения, возвращается новым раундом ревью, а коммита на ветке не остаётся. `finish --unreviewed` обходит эти проверки только по твоему прямому указанию и записывает этот выбор в коммит и отчёт. Прежде чем коммитить после code-ревью, попроси Claude запустить `verify`; если содержимое отличается от проверенного, Claude вернёт его движку командой `reply`, которую напечатает раннер. Пути помечаются как `covered`, `edited-after-review` или `never-reviewed`.

**Цитаты в замечаниях.** Каждое замечание цитирует строки, о которых оно. До записи раунда новые или изменённые цитаты открытых замечаний сверяются со снимком, который прошёл ревью, и получают метку `ok`, `moved:<L>` (найдена в строке L), `other_file:<F>` (найдена в файле F), `MISSING` или `unchecked`. Ответы, закрывающие замечание, и неизменённые цитаты сохраняют прежнюю метку. Проблемы с цитатами видны в сводке и промптах, отчёт хранит метки, а `/duet` отмечает ненайденные цитаты и цитаты из другого файла только у открытых замечаний. Метка не закрывает замечание и не меняет решение об остановке; `MISSING` — повод запросить новую цитату, а не отклонить замечание.

**Квитанции проверок.** В ревью и build рядом с DONE стоит метка проверки. За ней стоит *квитанция*: раннер сверяет команды, которые движок, по его словам, запускал, с событиями команд, сохранёнными из его хода, и показывает результаты, пропуски с причинами, неподтверждённые или противоречащие событиям утверждения и пробелы в сводке, `report.md` и `/duet`. Метки: `executed` (все проверки подтверждены, без пропусков и пробелов), `partial` (часть подтверждена, покрытие неполное), `static-analysis-only` (ни одна не подтверждена) и `unknown` (старый ответ без квитанции). Подтверждённое падение тоже может быть `executed`. Метка не меняет решение об остановке и не учитывает проверки, которые Claude сам запускает при ревью build.

## Панель `/duet` и защита

Мод раз в 2 секунды читает файлы сессий и показывает ревью, которое ведёт **эта** сессия Claude: раннер записывает, из какой сессии его вызвали (`CLAUDE_CODE_SESSION_ID`), и обновляет это на каждом ходе. Продолжишь ревью из другой сессии — первый же `reply` или `retry` переведёт его туда. Чужое ревью видно только в панели `/duet`, с пометкой и без кнопок решений; строки над промптом, футера, тостов и звуков от него нет. Ревью, начатые до 0.6.0, без отметки владельца и показываются везде, как раньше.

| Где | Что |
|---|---|
| **Панель** (`/duet`) | Всё о сессии; см. список ниже |
| **Строка над промптом** и статус-строка | Этап, таймер, текущее действие движка; строки других модов остаются под ней |
| **Футер** | Метка вроде «Duet r3 ⏳ 4:12», по нажатию открывает панель. Видна, даже если строка над промптом выключена |
| **Тосты** | Начало и конец раунда, эскалация, сбой; после раунда подсказка «продолжай agent-duet» (Tab) |
| **Звук** | Эскалация (нужно твоё решение), конец ревью, сбой раунда или пропавший процесс движка; ходы самого Claude звука не дают. Звучат штатные сигналы приложения Claude `tool_approval_needed`, `enter_voice_mode` и `disconnected`: их играет приложение, в плагин они не копируются. Без приложения звучат запасные из `sounds/` |

Панель сверху вниз:

- **Список задач**, когда их несколько: ⏳ идёт, ⏸ в очереди с местом, 🙋 нужен ты, ✅ готово, с таймером и моделью. Строка открывает подробности задачи.
- **Состояние**: этап и таймер раунда; модель и уровень, ⚡ Fast только у ходов Codex, которые идут в Fast; «Сейчас: …» с текущей командой движка или «думает N мин», если поток его событий молчит больше двух минут, и давность обновления журнала разговора, если она известна (журнал треда Codex растёт, даже когда он думает молча).
- **Слова движка**: его последнее сообщение целиком, отрисованное как Markdown (абзацы, списки, `код`), с возрастом, если оно старше двух минут; его действия («запускает тесты …», «запускает скрипт Python»); его план.
- **Доска замечаний**: ● открыто, ⏸ отложено, ✓ исправлено, ↩ снято, ⚔×N споров и полоса ▰▱ с долей закрытых (N/M). Заголовки переносятся, а не обрезаются; ▸ разворачивает, что сказали обе стороны; закрытые свёрнуты, пока есть открытые.
- **При эскалации**: позиции движка и Claude, кнопки выбора стороны, которая права, и «Отправить решения Claude».
- **Внизу**: табло, история раундов, кнопка «Стоп» (останавливает и ход в очереди) и свёрнутые «Настройки».

Текст панели переносится по ширине; обрезаются только строки списка задач и команды движка.

### Цикл не останавливается сам

Если сессия ждёт Claude (ответить на замечания или проверить раунд build), а Claude закончил ход, мод один раз возвращает его в цикл через хук `Stop`. Он не делает этого, если:

- Claude задал тебе вопрос;
- ты написал сообщение, и Claude ответил на него, не трогая цикл;
- идёт фоновая задача или запланировано пробуждение сессии;
- сессия ждёт твоего решения (эскалация);
- Claude только что уже возвращали в цикл.

### Защита от коммитов

Пока идёт code-ревью или build (и ещё 12 часов после его последнего хода), Claude ни в одной сессии не может сделать `git commit`, `push` или `stash` в этом репозитории (в build — в его worktree). Защита ловит случайные промахи Claude; это не песочница.

- **Распознаётся:** пути в кавычках, `cd`/`pushd`, глобальные опции Git, присваивания переменных окружения, команды-обёртки, составные команды, подстановки, `eval`, shell с `-c` и heredoc, переданный shell. Если заданы и Git-каталог, и рабочее дерево, запись блокируется, когда хотя бы один из них входит в защищаемое дерево.
- **Блокируется на всякий случай:** запись через Git с каталогом, зависящим от переменных, подстановок или glob-шаблонов, пока есть хоть одна защищаемая сессия. Если разбор команды не удался (например, из-за чрезмерной вложенности), при защищаемой сессии блокируется любая команда со словом `git`; остальные проходят.
- **Проходит:** упоминания в кавычках, комментарии, heredoc с данными, `stash list` и `stash show`.
- **Не распознаётся:** Git-алиасы (`git ci`, `git -c alias.x=commit x`), скрипты и Makefile, которые коммитят (`sh release.sh`, `npm run release`), и другие команды, собранные во время выполнения.

### Контекст после сжатия

К твоим сообщениям в проекте ревью прикладывается сводка сессии, поэтому Claude не теряет цикл после сжатия контекста. Уведомления о фоновых задачах её не получают: вывод раннера и так содержит всё. Сводка и возврат в цикл работают только в той сессии Claude, которая ведёт ревью.

### Команды панели

`/duet` открывает панель; `/duet stop` останавливает идущий раунд (продолжить потом можно через `retry`); `/duet band|toasts|score|sound on|off` включает и выключает части интерфейса (те же кнопки есть в «Настройках» внизу панели); `/duet sound test` или кнопка «▶ Звуки» проигрывает все три сигнала по очереди. Мод никогда не пишет в файлы сессий, только оставляет одну строку следа `.ui-trace.json` для отладки.

### Как выбрать модель agy

Обычно указывают семейство и уровень: `--model gemini-4-carbon --effort high`. Пару «модель и уровень» agy называет *slug*, например `gemini-3.8-flash-low`; список даёт `agy models`. Slug, отображаемое имя и имя семейства принимаются в любом регистре.

- **Семейство** (`gemini-4-carbon`) принимает только те уровни, которые `agy models` для него перечисляет. Без `--effort` уровень выбирает agy.
- **Slug** (`gemini-3.8-flash-low`) фиксирует уровень. Тот же `--effort low` допустим, другой уровень отклоняется с советом передать семейство. Смена только `--effort` через `reply`, `review` или `retry` заменяет уровень сохранённого slug.
- **Один `--effort`** применяется к семейству модели из `settings.json` agy.
- **Модели без уровней** `--effort` передаётся как есть, с пояснением: как agy его понимает, не проверялось.

Раннер вызывает `agy models` не чаще одного раза за запуск, с тайм-аутом 15 секунд. Если каталог недоступен или, при выборе только уровня, модели из `settings.json` нет или она неизвестна, соответствующая проверка пропускается с пояснением; пять имён уровней всё равно проверяются. Сводка, запись раунда и панель показывают итоговый slug и отдельно помечают семейство из `settings.json` и выбранный тобой уровень. Если передано только семейство, выбранный slug сообщает стартовое событие agy (`init`). Без каталога показывается твой выбор как есть, slug не придумывается.

`AGENT_DUET_AGY_HOME` задаёт, где плагин читает настройки и журналы разговоров agy (по умолчанию `~/.gemini/antigravity-cli`). Сам agy это не перенаправляет: укажи каталог, который agy действительно использует. Для входа сохраняется настоящий `HOME`.

### Как выбрать модель Codex

`--model` и `--effort` по умолчанию берутся из `~/.codex/config.toml`; можно и словами: «делегируй Codex, модель астра, уровень max». Раннер сверяет выбор с кешем моделей (`~/.codex/models_cache.json`) и откажет до запуска, перечислив доступное, если:

- такой модели нет (укажи ID вроде `gpt-6-astra` или название вроде `GPT-6-Astra`);
- такого уровня нет;
- модель не поддерживает этот уровень, в том числе тот, что стоит по умолчанию в `config.toml`.

Если кеша нет, проверка пропускается. Строка `Model:` в сводке раунда показывает, на чём идёт сессия.

### Fast (только Codex)

Отдельного флага нет: режим скорости Codex берёт из `config.toml` (`service_tier = "priority"`, так Fast называется в каталоге моделей). Значок ⚡ в строке над промптом, в списке задач и в панели («Модель: … · ⚡ Fast») появляется, только когда известно, что ход идёт в Fast. Пометка «(из конфига)» значит, что Fast включён в конфиге и каталог предлагает его для этой модели; пометка пропадает, когда Codex записывает режим хода в журнал треда (запись `thread_settings_applied` в `~/.codex/sessions/…/rollout-…-<тред>.jsonl`). Если журнал показал обычный режим, значок снимается. Codex 0.160 делает такую запись в начале каждого продолженного хода, а в первом ходе нового треда её может не быть. У agy режима Fast нет.

## Язык

Настройка плагина `language` принимает `auto` (по умолчанию), `en` (английский), `ru` (русский) или `zh` (упрощённый китайский). Она действует на интерфейс плагина и на заметки и сообщения, которые он отправляет Claude; вывод раннера остаётся английским. При смене настройки мод перезагружается.

Чтобы выбрать русский из оболочки:

```bash
echo '{"language":"ru"}' | claude plugin configure agent-duet --values-stdin
```

Вместо `ru` можно указать `en`, `zh` или `auto`. `--values-stdin` читает JSON-объект с однострочными строками; неуказанные настройки сохраняют текущие значения. Без `--values-stdin` команда `claude plugin configure agent-duet` только показывает конфигурацию. Сменить язык можно и в строке плагина в меню `/plugin`.

**Как `auto` выбирает язык.** Берётся первая непустая переменная из `LC_ALL`, `LC_MESSAGES` и `LANG`, именно в этом порядке: значение, начинающееся с `ru`, выбирает русский, с `zh` — китайский, любое другое — английский. Только если все три не заданы или пусты, на macOS берётся первый предпочитаемый язык из `AppleLanguages` с тем же правилом. На других платформах, при пустом списке или ошибке чтения используется английский.

## Безопасность

- Каждый движок работает со своей обычной настройкой: твой конфиг, модель, уровень, настроенные MCP-серверы и другие доступные ему инструменты.
- `--sandbox inherit` использует собственные разрешения движка. Для Codex явный режим применяется на каждом ходе: `-s` на старте и `-c sandbox_mode=…` на `resume`, потому что у `resume` нет флага `--sandbox`. Соответствия для agy приведены в разделе [Различия движков](#различия-движков).
- **Read-only у agy — обещание и проверка после хода, а не принудительная песочница.** Он запрещает `write_file`, но shell-команды могут писать. До и после каждого read-only хода раннер снимает отпечатки tracked и untracked неигнорируемых файлов в рабочем каталоге Git-репозитория; вне Git проверяется ограниченный набор файлов. Обнаруженные изменения записываются и показываются в предупреждении, но не откатываются. Игнорируемые файлы, пути вне рабочего каталога, файлы сверх лимита и изменения, отменённые до проверки, могут остаться незамеченными. Такая проверка не делает запуск недоверенного кода безопасным.
- **Запреты править файлы на ревью, коммитить и менять внешние системы — инструкции в промпте.** Для внешних PR и скачанных файлов выбирай `--sandbox read-only`: у Codex это даёт его shell-песочницу, у agy — только описанные выше обещание и проверку.
- **Не рассчитывай, что shell-песочница ограничивает MCP-инструменты.** У движка могут быть MCP-инструменты с записью во внешние системы, например в боевую базу. Промпт запрещает изменения через любые инструменты, но это инструкция, а не принудительное ограничение.
- **Окна связки ключей macOS, когда программа запущена с временным `HOME`.** Тесты и смоук-запуски иногда стартуют программу с `HOME` во временном каталоге, например `claude -p`, запущенный сессией Claude, которая ведёт build. Программы, которые входят через связку ключей (`claude`, `gh`, помощники git для паролей, `security`), не находят её там, и на каждую попытку появляется окно «связка ключей не найдена», которое висит, пока его не закроешь. **Жми «Отменить»:** «Сбросить настройки по умолчанию» создаёт новую пустую связку ключей вместо твоей. Ссылка на `~/Library/Keychains` во временном `HOME` окна убирает, но отдаёт программе всю твою связку, элементы которой потом можно поменять через `securityd`. Поэтому промпты движка (build и ревью) и правила для Claude в `SKILL.md` требуют давать вход через окружение, `CLAUDE_CODE_OAUTH_TOKEN` (его создаёт `claude setup-token`) или `GH_TOKEN`, и велят агенту спросить тебя, если их нет.

## Переход с codex-duet

До версии 0.12.0 плагин назывался codex-duet. Всё переходит без ручных шагов:

- **Сессии.** При первом вызове раннер переносит старый каталог состояния по умолчанию (`…/codex-duet`, обычно `~/.local/state/codex-duet`) в новый (`…/agent-duet`) и оставляет на старом месте симлинк, чтобы старые абсолютные пути продолжали работать, например у запущенных процессов и у worktree старых build. Если оба каталога существуют, используется только новый. Каталог, явно заданный через `AGENT_DUET_HOME` или `CODEX_DUET_HOME`, никогда не переносится. Мод эти пути только читает, а его файл следа для отладки (`.ui-trace.json`) лежит рядом с сессиями.
- **Переменные окружения.** Имена `CODEX_DUET_*` продолжают работать; см. [Переменные окружения](#переменные-окружения).
- **Ветки.** Ветки build с именами `codex-duet/<id>` по-прежнему распознаются; новые называются `agent-duet/<id>`.
- **Состояние панели.** Claude Code хранит состояние мода между горячими перезагрузками. Твои настройки, выбранная задача, решения, отмеченные в панели, и развёрнутые замечания переносятся из codex-duet один раз; собственные настройки agent-duet имеют приоритет.
- **Язык.** Язык, сохранённый для codex-duet, используется, пока ты не настроишь agent-duet, в том числе явным выбором `auto`.

## Неполадки

### agy (проверено с 1.5.7)

- **Нет вывода на старте.** Прежде чем начать, agy ждёт подключения всех настроенных MCP-серверов. Проверь VPN и сеть и выполни `agy mcp list` с тем же конфигом agy: один недоступный сервер может задержать ход. Очередь и тайм-аут фоновой команды продолжают действовать.
- **Инструменту отказано в доступе.** В headless-ходе agy не может спросить у тебя разрешения. Настрой нужные allow rules в agy или явно выбери `--sandbox danger-full-access` (`--dangerously-skip-permissions`). `workspace-write` использует `--sandbox` с настройками proceed-in-sandbox; это не отменяет все правила инструментов.
- **Retry начинает заново.** Проверь, что `.db` сохранённого разговора всё ещё лежит в `AGENT_DUET_AGY_HOME` (по умолчанию `~/.gemini/antigravity-cli`). `retry` использует `--conversation`, только когда файл на месте; `--fresh` начинает заново намеренно.
- **Нарушение read-only.** Посмотри записанные пути и файлы, прежде чем продолжать. Проверка предупреждает после хода и никогда не откатывает изменения. Она ловит не каждую запись; см. [Безопасность](#безопасность).

### Подводные камни Codex CLI (0.159)

- `codex exec` ждёт EOF на stdin, если stdin не терминал, и молча висит. Раннер передаёт промпт через stdin и закрывает его.
- `codex exec resume` не принимает `--sandbox`, `--cd` и `--color`.
- `-c 'mcp_servers={}'` не отключает MCP: значения сливаются, а не заменяются.
- `codex mcp list --json` печатает env серверов **без маскировки**, включая токены.

## Разработка

Клон в `~/.claude/skills/agent-duet` Claude Code подхватывает сам, без установки. Плагины Claude Code называет `<имя>@<источник>`: этот плагин — `agent-duet@agent-duet`, если он установлен из маркетплейса этого репозитория, и `agent-duet@skills-dir`, если это клон в `~/.claude/skills`. Правки доходят до новых сессий. Не ставь при этом тот же плагин из маркетплейса: установленный плагин побеждает одноимённый skills-dir, и клон показывается как «Not loaded».

## Тесты

```bash
node tests/run.mjs
node tests/mod.mjs
claude plugin test .
claude plugin validate .
```

Запускать из папки плагина. `run.mjs` и `mod.mjs` идут и в GitHub Actions (`.github/workflows/tests.yml`) на macOS и Linux.

`run.mjs` проверяет раннер на фейковом Codex (`tests/fake-codex.mjs`): журнал, споры, эскалацию, `retry`, read-only на `resume`, diff между раундами и причины решений политики на английском. В него входят и наборы проверок, совместимости и agy на фейковом agy (`tests/agy.mjs`); набор agy можно запустить и отдельно через `node tests/agy.mjs`, ему не нужны ни настоящий agy, ни сеть.

`mod.mjs` транспилирует настоящий `hooks/register.tsx` вместе с его локальными статическими импортами и прогоняет его хуки на заглушке среды плагинов Claude Code (`tests/mod-engine.mjs`). Сессии для него создаёт `duet.mjs` с тем же фейковым Codex. Тесты покрывают панель, строку над промптом, футер, тосты, звук, возврат в цикл, защиту от коммитов и сводку, в том числе английский по умолчанию, явно выбранные русский и китайский, приоритет локали в `auto`, выбор предпочитаемого языка macOS и английский при ошибке чтения, переводы сообщений и решений для сессии и совпадение ключей трёх таблиц переводов. Для транспиляции нужен esbuild (подойдёт тот, что внутри глобального `tsx`) или `typescript`; путь задаётся через `ESBUILD` или `TYPESCRIPT`. Заглушка ловит ошибки логики, но не ошибки в понимании API плагинов: новые вызовы API сверяй с `claude-code.d.ts` и `claude plugin validate`. Идея взята из plan-progress ([zycck/claude-mods](https://github.com/zycck/claude-mods)).

`tests/pane.test.tsx` рисует панель через собственный тестовый набор плагинов Claude Code (`claude plugin test`) на поверхностях terminal, desktop и mobile на английском, русском и китайском. Таблица элементов каждой поверхности проверяет дерево, чего заглушка не умеет. Сессия ревью лежит в памяти теста. Тесты проверяют, что длинные заголовки и пометка о чужой сессии видны целиком, что замечания разворачиваются и что слова движка идут как Markdown; узкая раскладка в 44 колонки проверяет и переносы китайских символов двойной ширины.

## Отключить или удалить

```bash
claude plugin disable agent-duet@agent-duet
claude plugin uninstall agent-duet@agent-duet
```

Клон в `~/.claude/skills` отключается так же, с именем `agent-duet@skills-dir`, а удаляется вместе с папкой.
