# agent-duet

Ревью, в котором Claude и выбранный движок, **Codex или agy (Antigravity CLI)**, договариваются сами. Движок находит замечания, Claude по каждому либо исправляет, либо возражает с доказательствами, либо откладывает для тебя. Цикл продолжается, пока они не согласятся, не упрутся в тупик или не кончатся раунды. Копировать текст между чатами не нужно.

Работает и в обратную сторону: в режиме **build** код пишет движок, а Claude работает архитектором и ревьюером. Так тратится в основном лимит выбранного движка. Скилл запускается командой `/agent-duet`, панель — `/duet`. Все пять режимов (`plan`, `code`, `file`, `build`, `audit`) работают с обоими движками; по умолчанию используется Codex.

Чтобы работа сверялась с твоими словами, в ревью можно передать `start --brief <file|->`: Markdown с разделами `## Owner's request` (дословная просьба, обязателен), `## Accepted amendments` (только принятые тобой поправки с источниками) и `## Claimed result` (заявление автора о результате). В build первый раздел обязателен в самой спецификации, поправки необязательны; отдельный `--brief` не используется, а audit brief не принимает. Движок и, перед одобрением build, Claude независимо заполняют `request_check`; сужение запроса в ревью или разногласие сторон в build передаётся тебе на решение. Проверки видны в сводке, `status` и отчёте.

Одобрение привязано к дереву, которое прошло ревью. В build `finish` сверяет и worktree, и коммит после хуков; изменившееся содержимое возвращается новым раундом ревью, а коммита на ветке не остаётся. `finish --unreviewed` обходит проверки только по твоему прямому указанию и записывает это в коммит и отчёт. Перед ручным коммитом после code-ревью запусти `verify`; если содержимое отличается, верни его движку командой `reply`, которую напечатает раннер. Пути отмечаются как `covered`, `edited-after-review` или `never-reviewed`.

До записи раунда новые или изменённые цитаты открытых замечаний сверяются со snapshot, который прошёл ревью: `ok`, `moved:<L>`, `other_file:<F>`, `MISSING` или `unchecked`. При закрытии замечания или повторе цитаты сохраняется прежняя проверка. Проблемы цитирования видны в сводке и промптах, отчёт сохраняет метки, а `/duet` отмечает ненайденные цитаты и цитаты из другого файла только у открытых замечаний. Метка не закрывает замечание и не меняет решение об остановке; `MISSING` — повод запросить новую цитату, а не автоматически отклонить замечание.

До версии 0.12.0 включительно плагин назывался **codex-duet**: сессии, сохранённые настройки панели, переменные окружения и ветки `codex-duet/` продолжают работать автоматически. При первом вызове раннер переносит старый каталог состояния по умолчанию в новый и оставляет симлинк, сохраняющий старые абсолютные пути; если оба каталога уже существуют, используется только новый. Явно заданный каталог не переносится. Панель лишь читает эти пути, а её файл следа хранится рядом с сессиями. Сохранённый язык используется как запасной до настройки нового плагина, включая явный выбор `auto`. Значения atom переживают горячую перезагрузку: настройки и доступные выборы интерфейса переносятся один раз, новые настройки имеют приоритет.

## Установка

Нужны:

- Claude Code 2.1.275 или новее;
- Установленный движок, в котором выполнен вход: [Codex CLI](https://github.com/openai/codex) с `codex` в `PATH` или agy (Antigravity CLI; проверено с 1.5.7) с `agy` в `PATH`. Другой бинарник задают `AGENT_DUET_CODEX_BIN` или `AGENT_DUET_AGY_BIN`;
- Node.js 22 или новее: раннер запускается как `node scripts/duet.mjs`;
- git для режимов code и build.

В терминальной сессии Claude Code:

```
/plugin install agent-duet --marketplace VScheglov/agent-duet
```

На вопрос `Add marketplace?` ответь `y` и выбери область: с user плагин работает во всех проектах. То же из оболочки:

```bash
claude plugin install agent-duet --marketplace VScheglov/agent-duet
```

В приложении Claude, где `/plugin` не работает, нажми + рядом с полем ввода, затем Plugins, Add marketplace с `VScheglov/agent-duet` и Add plugin.

Если `/agent-duet` и `/duet` после установки не видны, открой новую сессию или выполни `/reload-plugins`. Полное имя команды скилла `/agent-duet:agent-duet`, короткое `/agent-duet` работает, пока это имя не занято другой командой.

**Рекомендуется: 12 часов на фоновую команду.** Ход движка идёт долго, поэтому Claude запускает его в фоне с `timeout: 43200000`. Без настройки Claude Code обрежет это до 2 часов, и долгий ход оборвётся (продолжить его можно через `retry`). Чтобы этого не случалось, добавь в `~/.claude/settings.json`:

```json
{ "env": { "BASH_MAX_TIMEOUT_MS": "43200000" } }
```

Настройка действует в сессиях, открытых после правки.

## Язык

Настройка плагина `language` принимает `auto` (по умолчанию), `en` (английский), `ru` (русский) или `zh` (упрощённый китайский). В режиме `auto` берётся первая непустая переменная окружения из `LC_ALL`, `LC_MESSAGES`, `LANG`, именно в этом порядке: значение, начинающееся с `ru`, выбирает русский, с `zh` — китайский, любое другое — английский.

Только если все три переменные не заданы или пусты, на macOS берётся первый предпочитаемый язык из `AppleLanguages` с тем же правилом для `ru` и `zh`. Непустая переменная локали всегда имеет приоритет. На других платформах, при пустом списке предпочитаемых языков или ошибке чтения используется английский.

Чтобы выбрать русский из оболочки:

```bash
echo '{"language":"ru"}' | claude plugin configure agent-duet --values-stdin
```

Вместо `ru` можно указать `en`, `zh` или `auto`. `--values-stdin` читает JSON-объект со значениями в виде однострочных строк; неуказанные настройки сохраняют текущие значения. Без `--values-stdin` команда `claude plugin configure agent-duet` только показывает конфигурацию. Изменить язык также можно в строке плагина в меню `/plugin`.

При смене настройки модуль перезагружается. Настройка действует на интерфейс плагина и его заметки и сообщения для Claude; вывод раннера остаётся английским.

## Где работает

| Платформа | Что |
|---|---|
| macOS | всё |
| Linux | всё, кроме звука: у Claude Code на Linux нет проигрывателя, тосты и строка остаются. Блокировку сессии, оставшуюся от раннера, который убили через `kill -9` или который упал вместе с машиной, снимаешь руками: ошибка `stale lock` называет файл. На macOS ядро снимает такую блокировку само (`O_EXLOCK`) |
| Windows | не поддерживается: раннер и мод вызывают `kill`, `tail`, `head`, `grep` и `diff`. WSL должен вести себя как Linux, но не проверялся |

Если Claude Code управляется организацией (managed settings), хук `Stop` не запускается в плагинах, которые человек ставит сам. Тогда мод не возвращает Claude в цикл, когда тот закончил ход (см. «Цикл не останавливается сам»). Остальное работает.

## Использование

```
/agent-duet plan                      план из plan mode или из текущего разговора
/agent-duet code                      незакоммиченные изменения (вместе с untracked)
/agent-duet code --base main          вся ветка от merge-base с main
/agent-duet file docs/spec.md         любые файлы: тест-кейсы, SQL, спеки, конфиги
/agent-duet code -- проверь миграции  после `--` идёт фокус ревью
/agent-duet code --engine agy         ревью через agy
/agent-duet audit --engine agy        разовый аудит через agy (ограничения read-only ниже)
/agent-duet status                    где мы сейчас (пригодится и после сжатия контекста)
```

Можно и словами: «отдай Codex на ревью», «отдай agy на ревью», «делегируй agy», «проведи аудит через agy».

Движок выбирается при `start` опцией `--engine codex|agy`. Без неё берётся `AGENT_DUET_ENGINE`, затем `codex`. Выбор сохраняется в сессии: сменить движок через `reply`, `review` или `retry` нельзя, нужна новая сессия. Старые сессии без поля движка остаются сессиями Codex.

Общие опции: `--max-rounds N` (по умолчанию 10), `--model`, `--effort`, `--timeout-min` (лимит на ход; по умолчанию без ограничения), `--sandbox` (по умолчанию `inherit`). Модель и уровень можно менять через `reply`, `review` или `retry`.

## Различия движков

| Возможность | Codex | agy |
|---|---|---|
| Модели и уровень | Конфиг `~/.codex/config.toml`, каталог `~/.codex/models_cache.json` | Семейства из `agy models`; обычно `--model gemini-4-carbon --effort high`; уровни `low`, `medium`, `high`, `xhigh`, `max`; конфиг в `settings.json` |
| `inherit` | Разрешения твоего Codex | Без флагов разрешений; используются настройки agy |
| `workspace-write` | Песочница рабочего каталога Codex | `--sandbox` и настройки proceed-in-sandbox |
| `danger-full-access` | Полный доступ Codex | `--dangerously-skip-permissions` |
| `read-only`, включая любой audit | Песочница Codex с запретом записи из shell | Обещание и проверка отпечатков после хода; shell всё ещё может писать |
| Продолжение | Журнал треда в `~/.codex/sessions` | `--conversation <id>`, пока в каталоге agy есть `.db` разговора |
| Журналы | `round-N.events.jsonl` | Сырой `round-N.agy.jsonl` и нормализованный `round-N.events.jsonl` |
| Fast | Настраивается и подтверждается, как описано ниже | Нет режима и значка Fast |

У обоих движков разобранный ответ сохраняется как `round-N.codex.json`; ID сессий и внутренние поля состояния остаются прежними. `AGENT_DUET_AGY_HOME` задаёт каталог, где плагин читает настройки и журналы разговоров agy (по умолчанию `~/.gemini/antigravity-cli`). Это не перенаправляет сам CLI: укажи каталог, который использует agy. Для аутентификации сохраняется настоящий `HOME`.

Для agy обычно указывают семейство и уровень: `--model gemini-4-carbon --effort high`. Slug, отображаемое имя и имя семейства принимаются без учёта регистра. Slug вроде `gemini-3.8-flash-low` фиксирует уровень: тот же `--effort low` допустим, другой уровень отклоняется с советом передать семейство. Для семейства принимаются только уровни из каталога; без уровня его выбирает agy. Один `--effort` применяется к семейству модели из `settings.json`. Смена только `--effort` через `reply`, `review` или `retry` заменяет уровень сохранённого slug. Для отдельных моделей без уровней effort передаётся с пояснением: это поведение не проверено.

Раннер вызывает `agy models` не чаще одного раза за запуск, с тайм-аутом 15 секунд. Если каталог недоступен или модель из настроек неизвестна/отсутствует при выборе только effort, соответствующая проверка пропускается с пояснением; пять значений уровня выше всё равно проверяются. Сводка, запись раунда и панель показывают разрешённый slug, отдельно помечая семейство из конфига и явно выбранный уровень. Если передано только семейство, выбранный slug берётся из события init agy. Без каталога показывается переданный выбор, slug не придумывается. Fast у agy нет.

Для Codex `--model` и `--effort` по умолчанию берутся из `~/.codex/config.toml`; модель можно назвать словами: «делегируй Codex, модель астра, уровень max».

Для Codex модель и уровень раннер сверяет с кешем моделей (`~/.codex/models_cache.json`). Он откажет до запуска и перечислит доступное, если:

- такой модели нет (можно указать ID `gpt-6-astra` или название `GPT-6-Astra`);
- такого уровня нет;
- модель не поддерживает уровень, в том числе тот, что стоит по умолчанию в `config.toml`.

Если кеша нет, проверка пропускается. Строка `Model:` в сводке раунда показывает, на чём идёт сессия.

**⚡ Fast (только Codex).** Отдельного флага нет: режим скорости Codex берёт из `config.toml` (`service_tier = "priority"`: так Fast называется в каталоге моделей). Значок ⚡ в строке над вводом, в списке задач и в панели («Модель: … · ⚡ Fast») появляется, только когда известно, что ход идёт в Fast. Пометка «(из конфига)» значит, что Fast включён в конфиге, а в каталоге моделей он есть у этой модели. Пометка пропадает, когда Codex сам записывает режим хода в журнал треда (`~/.codex/sessions/…/rollout-…-<тред>.jsonl`, запись `thread_settings_applied`). Если журнал показал обычный режим, значок снимается. Codex 0.160 делает такую запись в начале каждого продолженного хода, а в первом ходе нового треда её может не быть.

**Время.** Ход движка идёт долго, build — особенно, поэтому Claude запускает `start`, `reply`, `review` и `retry` в фоне с `timeout: 43200000` (12 часов). Потолок фоновой команды в Claude Code — 2 часа, если его не поднять: `max(2 ч, BASH_MAX_TIMEOUT_MS)`. Как поднять до 12 часов, сказано в «Установке»; эта настройка заодно поднимает до 12 часов и предел тайм-аута для команд на переднем плане. Тайм-аут выше потолка Claude Code молча обрезает до потолка. На переднем плане команда без явного `timeout` живёт 2 минуты, в фоне — 30. Своего лимита на ход у раннера по умолчанию нет, задать его можно через `--timeout-min N`. Сессии, начатые до 0.6.0, хранят старый лимит в 60 минут; снять его можно командой `retry --timeout-min 0` (или с `reply`/`review`).

**Оборванный ход.** Если ход оборвался после начала работы движка (кончилось время фоновой команды, нажали «Стоп», CLI упал), `retry` продолжает тот же разговор с коротким промптом «продолжи с того места», даже в первом раунде. Сделанная работа и прочитанное остаются в контексте, пока доступен разговор: Codex нужен журнал треда в `~/.codex/sessions`, agy — `.db` разговора в своём каталоге; agy продолжает его с `--conversation`. Если нужного файла нет, ход начинается заново. `retry --fresh` всегда начинает заново; сделанное на диске он не отменяет.

**Несколько задач сразу.** Можно делегировать сразу несколько задач: у каждого build свой worktree и своя ветка. Одновременно на машине идут не больше десяти ходов движков (`AGENT_DUET_MAX_PARALLEL`), остальные ждут в очереди (фаза `queued`) в порядке постановки и стартуют сами, как освободится слот. Каждый ход движка поднимает все MCP-серверы из конфига и тратит одну квоту, поэтому без очереди десять задач — это сотни процессов. Слот держится только пока работает движок; пока Claude ревьюит, он свободен. Ожидание в очереди засчитывается в двухчасовой потолок фоновой команды, так что лучше ставить по несколько задач, а не десятки сразу.

## Режим build: движок пишет, Claude ревьюит

```
/agent-duet build --engine agy        «делегируй agy …», «пусть agy реализует …»
```

1. Claude пишет спецификацию: цель, границы, ограничения, критерии приёмки, как проверять.
2. Раннер создаёт ветку `agent-duet/<id>` в отдельном worktree от HEAD. Твоё рабочее дерево не трогается. Незакоммиченное движок не видит.
3. Движок реализует, гоняет тесты и отчитывается: что сделал, что проверил, что под вопросом.
4. Claude смотрит дифф раунда, сам запускает тесты в worktree и поднимает замечания C1…Cn. Движок исправляет или возражает. Политика остановки та же, тупики приходят к тебе (и в панель `/duet`).
5. Когда всё сошлось, с твоего согласия `finish` коммитит работу в ветку и убирает worktree, а сливаешь ты сам. Заголовки Conventional Commits (включая scope и `!`) сохраняются; к прочим добавляется `agent-duet: `, если имя плагина ещё не указано. Тело коммита называет движок, выполнивший работу, и ревью Claude. `discard` удаляет и worktree, и ветку.

Подробности для Claude лежат в `references/build.md`.

В review и build рядом с DONE стоит метка проверки: `executed` (все проверки подтверждены, нет пропусков и пробелов), `partial` (часть подтверждена, покрытие неполное), `static-analysis-only` (ни одна не подтверждена) или `unknown` (старый ответ). Квитанция сверяет заявленные команды с сохранёнными событиями и показывает результаты, причины пропусков, неподтверждённые и противоречащие событиям утверждения и пробелы в сводке, `report.md` и `/duet`. Подтверждённые падения допускают `executed`; метка не меняет решение об остановке и не включает собственные проверки Claude при build-ревью.

## Режим audit: движок проверяет, ничего не меняя

```
/agent-duet audit --engine agy        «проведи аудит через agy …», «пусть agy проверит … и даст отчёт»
```

Разовый отчёт без переговоров: аудит кода, данных, эталона, политики. Поэтому Claude не тратит токены на ответ по каждому замечанию. Если эталон нельзя править без твоего `APPROVED`, ревью здесь не подходит: почти всё ушло бы к тебе. Не подходит и build: аудит ничего не должен менять.

1. Claude пишет задание: что проверить и на какой вопрос ответить, границы, что считать находкой, что вынести в заметки (рейтинг, таблицу).
2. Движок работает прямо в папке проекта, всегда с `read-only`: `--sandbox` с другим значением раннер не примет. Codex применяет песочницу с запретом записи из shell. У agy это обещание и проверка после хода, а не изоляция с запретом записи: `write_file` запрещён, но shell-команды могут писать. Обнаруженные изменения записываются и показываются в предупреждении, но не отменяются. Записи через MCP запрещены промптом, не песочницей (см. «Безопасность»).
3. Один ход. На выходе итог, находки A1…An (важность, место, доказательства, рекомендация, уверенность) и что проверено, а что нет. В сводке Claude видит по строке на находку, всё остальное лежит в `report.md` сессии.
4. Отвечать не на что: `reply` и `review` для аудита отказывают. Нужен другой угол — новый аудит с более точным заданием. Находки остаются утверждениями движка: перед тем как на них опираться, Claude проверяет нужные или говорит, что они не проверены.

Очередь, панель (`/duet` показывает итог и находки), 12 часов на ход и `retry` с продолжением разговора работают так же, как в остальных режимах. Fast остаётся только у Codex.

## Как идут переговоры

```
start ─► движок: замечания C1…Cn (JSON по схеме)
          │
          ▼
   Claude по каждому замечанию:  fixed · disputed · needs-user
          │
reply ─► движок (та же сессия, resume): resolved · withdrawn · open + контраргумент · новые
          │
          ▼
   scripts/policy.mjs → continue · done · escalate (тупик → тебе)
```

- У каждого замечания постоянный ID. Движок видит ответы Claude и diff между раундами.
- Если ты решил спор в пользу текущей версии (`owner-decided`), замечание закрывается, даже если движок с этим не согласен.
- Когда раунды кончаются, всегда происходит эскалация, что бы ни сказала политика.
- Claude ничего не коммитит.

## Политика остановки (`scripts/policy.mjs`)

Правила проверяются сверху вниз, срабатывает первое подходящее:

1. Claude отложил решение с severity critical/high (`needs-user`) → **escalate** сразу.
2. Движок говорит `approve`, открытых critical/high нет → **done**. Medium/low уходят в отчёт, остальное отложенное приносится тебе.
3. Движок 2 раза отклонил возражения по одному замечанию → **escalate** (тупик).
4. Два раунда подряд открытых замечаний не становится меньше → **escalate** (застой).
5. Иначе → **continue**.

Пороги задаются константами `MAX_DISPUTES` и `STALL_ROUNDS`. Если меняешь правила, поправь и тесты `policy …` в `tests/run.mjs`.

## Панель `/duet` и защита

В плагине есть мод Claude Code (`hooks/register.tsx`). Раз в 2 секунды он читает файлы сессий и показывает ревью, которое ведёт **эта** сессия Claude: раннер записывает в состояние, из какой сессии Claude его вызвали (`CLAUDE_CODE_SESSION_ID`), и при каждом ходе обновляет. Продолжишь ревью из другой сессии — первый же `reply` или `retry` переведёт его туда. Чужое ревью видно только в панели `/duet`, с пометкой и без кнопок решений; строки, футера, тостов и звуков от него нет. Ревью, начатые до 0.6.0, без отметки владельца, показываются везде, как раньше.

| Где | Что |
|---|---|
| **Панель** `/duet` | при нескольких задачах — список сверху (⏳ идёт, ⏸ в очереди с местом, 🙋 нужен ты, ✅ готово; таймер, модель), строка открывает подробности задачи; дальше этап и таймер раунда; модель и уровень хода, ⚡ Fast только у Codex, если ход идёт в Fast; «Сейчас: …» — команда движка или «думает N мин», если поток его событий молчит больше двух минут, и давность обновления журнала разговора, если она доступна: журнал треда Codex растёт, даже когда он думает молча; последние слова движка целиком, с абзацами, списками и `кодом` (рисуются как markdown), с возрастом, если они старше двух минут, и его действия («запускает тесты …», «запускает скрипт Python»); его план; доска замечаний (● открыто, ⏸ отложено, ✓ исправлено, ↩ снято, ⚔×N споров) с полосой «закрыто N из M»: заголовки переносятся под себя, а не обрезаются, ▸ у замечания разворачивает, что сказали обе стороны, закрытые свёрнуты, пока есть открытые; табло и история раундов; кнопка «Стоп» (останавливает и ход в очереди); внизу свёрнутые «Настройки». Текст панели переносится по ширине, обрезаются только строки списка задач и команд движка |
| ↳ при эскалации | позиции движка и Claude и кнопки выбора стороны, которая права, затем «Отправить решения Claude» |
| **Строка над промптом** и статус-строка | этап, таймер, текущее действие движка; строки других модов остаются под ней |
| **Футер** | метка вроде «Duet r3 ⏳ 4:12», по нажатию открывает панель; видна, даже если строка над промптом выключена |
| **Тосты** | начало и конец раунда, эскалация, сбой; после раунда подсказка «продолжай agent-duet» (Tab) |
| **Звук** | эскалация (нужно твоё решение), конец ревью, сбой раунда или пропавший процесс движка; ходы Claude звука не дают. Звучат штатные сигналы приложения Claude: `tool_approval_needed`, `enter_voice_mode`, `disconnected`. Они играют прямо из приложения и в плагин не копируются. Без приложения звучат запасные из `sounds/` |

**Цикл не останавливается сам.** Если сессия ждёт хода Claude (ответить на замечания или в build проверить раунд движка), а Claude закончил ход, мод один раз возвращает его в цикл через хук `Stop`. Он не делает этого, если:

- Claude задал тебе вопрос;
- ты написал сообщение, и Claude ответил на него, не трогая цикл;
- идёт фоновая задача или запланировано пробуждение сессии;
- сессия ждёт твоего решения (эскалация);
- Claude только что уже возвращали.

Возврат и сводка работают только в той сессии Claude, которая ведёт ревью.

Пока идёт code-ревью или build (активными они считаются 12 ч после последнего хода), Claude ни в одной сессии не может сделать `git commit`, `push` и `stash` в этом репозитории (в build — в его worktree). Защита разбирает исполняемые shell-команды: пути в кавычках, `cd`/`pushd`, глобальные опции Git, присваивания переменных окружения, команды-обёртки, составные команды, подстановки, `eval`, shell с `-c` и heredoc, переданный shell. Если одновременно заданы Git-каталог и рабочее дерево, запись блокируется, когда хотя бы один из этих путей входит в защищаемое дерево. Упоминания в кавычках, комментарии, heredoc с данными, `stash list` и `stash show` проходят. Запись через Git с каталогом, зависящим от переменных, подстановок или glob-шаблонов, блокируется при наличии любой защищаемой сессии. Если разбор команды завершается ошибкой (например, из-за чрезмерной вложенности), при наличии защищаемой сессии блокируются команды со словом `git`; остальные проходят. Git-алиасы (`git ci`, `git -c alias.x=commit x`), скрипты и Makefile, делающие коммит (`sh release.sh`, `npm run release`), и другие команды, собираемые во время выполнения, не распознаются. Защита поддерживает собственный запрет Claude и страхует от случайного нарушения; это не песочница.

К твоим сообщениям в проекте ревью прикладывается сводка сессии, поэтому Claude не теряет цикл после сжатия контекста. Уведомления о фоновых задачах её не получают: вывод раннера и так содержит всё.

Команды: `/duet` открывает панель, `/duet stop` останавливает идущий раунд (продолжить потом можно через `retry`), `/duet band|toasts|score|sound on|off` включает и выключает части интерфейса (то же делают кнопки в свёрнутом блоке «Настройки» внизу панели), `/duet sound test` или кнопка «▶ Звуки» проигрывает все три сигнала по очереди. Мод ничего не пишет в файлы сессий, только оставляет одну строку следа `.ui-trace.json` для отладки.

## Безопасность

- Каждый движок работает с **полным собственным харнессом**: твой конфиг, модель, effort, настроенные MCP-серверы и другие доступные инструменты.
- `--sandbox inherit` использует разрешения выбранного движка. Для Codex явные режимы применяются на каждом ходе: `-s` на старте и `-c sandbox_mode=…` на `resume`, потому что у `resume` нет флага `--sandbox`. Соответствия для agy приведены в таблице выше.
- **Read-only у agy — обещание и проверка после хода, а не песочница с запретом записи.** Его sandbox запрещает `write_file`, но shell-команды могут писать. Перед каждым read-only ходом и после него раннер снимает отпечатки tracked и untracked неигнорируемых файлов под cwd в Git-репозитории; вне Git проверяется набор с ограничением размера. Обнаруженные нарушения записываются и показываются в предупреждении без отката изменений. Игнорируемые файлы, пути вне cwd, файлы за пределами лимита и изменения, отменённые до проверки, могут остаться незамеченными. Такая проверка не делает запуск недоверенного кода безопасным.
- Запрет править файлы на ревью, коммитить и менять внешние системы — **инструкция в промпте**. Для внешних PR и скачанных файлов `--sandbox read-only` у Codex применяет его shell-песочницу; у agy остаётся описанным выше обещанием с проверкой.
- **Не рассчитывай, что shell-песочница ограничивает MCP-инструменты.** Ревьюер может иметь MCP с записью во внешние системы, например в боевую базу. Промпт запрещает изменения через любые инструменты, но это инструкция, не принудительное ограничение.
- **Связка ключей и подменённый `HOME` (macOS).** Программа, запущенная с `HOME` во временном каталоге (`claude`, `gh`, помощники git для паролей, `security`), не находит связку ключей macOS, и на каждую попытку входа macOS показывает окно «связка ключей не найдена». Окна висят, пока их не закроешь. В таких окнах жми «Отменить»: «Сбросить настройки по умолчанию» создаёт новую пустую связку ключей вместо твоей. Ссылка на `~/Library/Keychains` окна убирает, но отдаёт программе всю твою связку: её элементы меняются через securityd. Поэтому промпты движка (build и ревью) и правила для Claude в SKILL.md требуют давать таким программам вход через окружение: `CLAUDE_CODE_OAUTH_TOKEN` (его создаёт `claude setup-token`) или `GH_TOKEN`. Если входа нет, нужно спросить. Такие окна вызывали, например, смоук-запуски `claude -p` в сессии Claude, которая вела сборку; сам Codex ни `claude`, ни `security` не запускал.

## Тесты

```bash
node tests/run.mjs
node tests/mod.mjs
claude plugin test .
claude plugin validate .
```

Запускать из папки плагина. `run.mjs` и `mod.mjs` идут и в GitHub Actions (`.github/workflows/tests.yml`) на macOS и Linux.

`run.mjs` проверяет раннер на фейковом Codex (`tests/fake-codex.mjs`): журнал, споры, эскалацию, `retry`, read-only на `resume`, diff между раундами и политику с причинами решений на английском. Он также включает набор на фейковом agy (`tests/agy.mjs`), который можно запустить отдельно через `node tests/agy.mjs`; настоящий agy и сеть не нужны.

`mod.mjs` транспилирует настоящий `hooks/register.tsx` вместе с его локальными статическими импортами и прогоняет его хуки на заглушке движка (`tests/mod-engine.mjs`). Сессии для него создаёт `duet.mjs` с тем же фейковым Codex. Проверяются панель, строка, футер, тосты, звук, возврат в цикл, защита от коммита и сводка. Языковые тесты проверяют английский по умолчанию, явно выбранные русский и китайский, приоритет локали в `auto`, выбор предпочитаемого языка macOS и английского при ошибке чтения, переводы сообщений и решений для сессии и совпадение ключей трёх таблиц переводов. Для транспиляции нужен esbuild (подойдёт тот, что внутри глобального `tsx`) или `typescript`; путь можно задать через `ESBUILD` или `TYPESCRIPT`. Заглушка ловит ошибки логики, но не ошибки в понимании API: новые вызовы движка сверяй с `claude-code.d.ts` и `claude plugin validate`. Идея взята из plan-progress ([zycck/claude-mods](https://github.com/zycck/claude-mods)).

`tests/pane.test.tsx` рисует панель через тестовый набор самого движка (`claude plugin test`) на поверхностях terminal, desktop и mobile на английском, русском и китайском: таблица элементов каждой поверхности проверяет дерево, чего заглушка не умеет. Сессия ревью лежит в памяти теста; проверяется, что длинные заголовки и пометка о чужой сессии видны целиком, замечание разворачивается, а слова Codex идут как markdown; узкая панель в 44 колонки проверяет переносы и для китайских символов двойной ширины.

## Неполадки agy (проверено с 1.5.7)

- **Нет вывода на старте.** agy ждёт подключения всех настроенных MCP-серверов. Проверь VPN/сеть и выполни `agy mcp list` с тем же конфигом agy: недоступный сервер может задержать ход. Очередь и тайм-аут фоновой команды продолжают действовать.
- **Инструменту отказано в доступе.** В headless-ходе нельзя показать интерактивный вопрос о разрешении. Настрой нужные allow rules в agy или явно выбери `--sandbox danger-full-access` (`--dangerously-skip-permissions`). `workspace-write` использует `--sandbox` и настройки proceed-in-sandbox; это не отменяет все правила инструментов.
- **Retry начинает заново.** Проверь, что `.db` сохранённого разговора всё ещё лежит в `AGENT_DUET_AGY_HOME` (по умолчанию `~/.gemini/antigravity-cli`). `retry` использует `--conversation`, только когда файл существует; `--fresh` намеренно начинает заново.
- **Нарушение read-only.** Посмотри записанные пути и файлы до продолжения. Проверка предупреждает после хода и никогда не откатывает изменения. Она не обнаруживает каждую запись; см. «Безопасность».

## Подводные камни Codex CLI (0.159)

- `codex exec` ждёт EOF на stdin, если stdin не терминал, и молча висит. Раннер передаёт промпт через stdin и закрывает его.
- `codex exec resume` не принимает `--sandbox`, `--cd` и `--color`.
- `-c 'mcp_servers={}'` не отключает MCP: значения сливаются, а не заменяются.
- `codex mcp list --json` печатает env серверов **без маскировки**, включая токены.

## Разработка

Клон в `~/.claude/skills/agent-duet` Claude Code подхватывает сам как `agent-duet@skills-dir`, без установки. Правки доходят до новых сессий. Не ставь при этом тот же плагин из маркетплейса: установленный плагин побеждает одноимённый skills-dir, и клон показывается как «Not loaded».

## Отключить или удалить

```bash
claude plugin disable agent-duet@agent-duet
claude plugin uninstall agent-duet@agent-duet
```

Клон в `~/.claude/skills` отключается так же, с именем `agent-duet@skills-dir`, а удаляется вместе с папкой.
